**Owns:** ISA, pipeline hazards, COP0 (TLB/cache/exceptions), COP1 FPU, N64-specific pin/errata notes.

## 1. Identity

| Item | Value |
|------|-------|
| Console CPU | NEC **VR4300** derivative (community: not “VR4300i”; R4300i is the MIPS part name) |
| ISA | **MIPS III** (32/64-bit integer + COP1); instructions always **32-bit** encoding |
| Clock | **93.75 MHz** |
| Pipeline | **5-stage** (IF/RF/EX/DF/WB class; see UM) |
| External data bus | **32-bit** SysAD (64-bit ops take extra bus beats) |
| L1 | **16 KiB I-cache** + **8 KiB D-cache** (VR4300 package figures; Copetti summary) |
| MMU | COP0 TLB — 32 entries class (confirm vs UM for exact) |

## 2. Programming model

### GPRs

32 general-purpose registers; **r0** hardwired zero. In 64-bit mode registers are 64-bit; 32-bit ops sign-extend into the full register (classic MIPS III rules — verify each op class against UM / torture tests).

### Modes

- **32-bit addressing mode** vs **64-bit addressing mode** (Status.KX/SX/UX and related).
- Privilege: User / Supervisor / Kernel — retail N64 software effectively stays in **kernel**.
- **EXL / ERL** bits alter exception vectoring and TLB refill behavior.

### Delay slots

- **Branch delay slots** remain (unlike load delay, which is interlocked on this generation).
- Some branch-likely encodings nullify the delay slot when not taken — implement carefully; suites catch this.

## 3. COP0 — system control

Must-have early:

| Concern | Notes for emulator |
|---------|-------------------|
| **Status / Cause / EPC / ErrorEPC** | IRQ enable, exception codes, BD bit |
| **Context / XContext / BadVAddr / EntryHi/Lo / Index / Random / Wired / PageMask** | TLB programming |

## 4. TLB and virtual memory

Software sees **KSEG0/KSEG1** direct maps for low 512 MiB physical, plus TLB-mapped kuseg/ksseg/kseg3.

Implementation checklist:

1. Translate VA→PA with correct segment rules before any bus probe.
2. Honor **cacheability** bits — cached MMIO kills real hardware ([00](./00-architecture-overview.md)).
3. 64-bit VA extensions exist in the architecture; N64 software rarely needs the huge map — still don’t crash on DMFC0 of wide regs ([n64-systemtest](https://github.com/lemmy-64/n64-systemtest) stresses 64-bit COP0).

---

## 5. Caches

- KSEG0 hits **cached** RDRAM paths; KSEG1 **uncached**.
- Instruction cache makes running from cart ROM via PI painfully slow if attempted uncached/wrong — games DMA code to RDRAM.
- Self-modifying code / DMA into code pages needs `CACHE` or I-cache invalidation discipline; wrong emu behavior here shows up as “random” crashes.

**Accuracy ladder:** (1) functionally correct cached vs uncached routing; (2) approximate miss penalties; (3) cen64-class timing.

## 6. COP1 — FPU

IEEE-754 single/double. On VR4300 the FPU is tightly coupled (not a true async coprocessor) but still programmed as COP1. Need:

- Full register file + FCC / FCSR rounding & flags
- LWC1/LDC1/SWC1/SDC1 alignment rules
- CU1 enable in Status — Coprocessor Unusable exceptions

Many early homebrew tests are integer-only; FPU becomes gating for commercial smoke quickly.

## 8. Interpreter vs dynarec

| Approach | Pros | Cons |
|----------|------|------|
| **Interpreter** | Debuggable; matches early gates | Slow for commercial + LLE RSP together |
| **Block dynarec** | Needed for playable LLE | Hard: self-mod, CACHE, precise exceptions, 64-bit |
| **Cached interpreter** | Mid | Complexity between the two |

**Plan posture ([08](./08-implementation-plan.md)):** ship a correct interpreter through CPU/bus gates; design `CpuBackend` trait so dynarec can land without rewriting RSP/RDP. Dynarec is **not** a substitute for wrong COP0/TLB.

## 9. Minimum ISA for first boot / suites

Order of attack (aligned with Dillonb / n64-systemtest guidance):

1. Integer ALU + branches + loads/stores (8/16/32/64) + delay slots  
2. COP0 MTC0/MFC0 (+ 64-bit DM* variants enough to not crash)  
3. Exceptions + IRQ path from MI  
4. TLB refill enough for suite maps  
5. FPU as suites/games demand  
6. `CACHE`, LL/SC hardening  

Soft-boot homebrew may jump to `0x80001000`-class entry after stubbing IPL — still need correct GPR/COP0 reset defaults (**TBD** table in provenance).
